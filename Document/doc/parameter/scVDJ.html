🔬 主分析流程 (run)

📊 用法 

$ dnbc4tools vdj run -h
usage: dnbc4tools vdj run [-h] 

optional arguments:
  -h, --help            show this help message and exit

Input Files:
  Choose ONE input method: either --fastqs (directory) OR individual FASTQ files (-1 and -2).

  --fastqs <DIR>        Input directory containing paired-end FASTQ files. The pipeline automatically detects Read1/Read2 files. Example: ./fastq_dir
  -1, --fastq1 <FILE> [<FILE> ...]
                        Read1 FASTQ file(s) (supports wildcards and comma-separated lists). Example: sample1_L01_R1.fastq.gz,sample1_L02_R1.fastq.gz
  -2, --fastq2 <FILE> [<FILE> ...]
                        Read2 FASTQ file(s) (supports wildcards and comma-separated lists). Must match --fastq1 order. Example: sample1_L01_R2.fastq.gz,sample1_L02_R2.fastq.gz

Basic Settings:
  -n, --name <STR>      Unique identifier for the sample (e.g., sample1). Used for naming output files and reports.
  -r, --ref REF         Reference database: 'human'/'mouse' (case-insensitive) or path to a custom reference directory containing reference.json. Examples: human | mouse | ./custom_vdj_ref
  -c, --chain <STR>     VDJ receptor type: 'IG' (B-cell receptors) or 'TR' (T-cell receptors).
  -o, --outdir <DIR>    Output directory for results and reports [default: current directory]. Example: ./output
  -t, --threads <INT>   Number of CPU threads for parallel processing [default: all available cores] (e.g., 16).
  -s, --beadstrans <FILE>
                        RNA analysis singlecell.csv file for filtering cells and merging beads information. When not provided, all cells will be kept by default (equivalent to --keep_all_cells).

Library Settings:
  Auto-detection is recommended for dark cycles. Available modes include "R1" and "unset".
  For multiple files, ensure consistent settings across all inputs.
  customize: Specify sequence structure patterns for parsing.

  --darkreaction <STR>  Dark cycle setting for VDJ library [default: auto]. Use 'R1' if dark cycles occur in Read1; otherwise leave as 'auto' or 'unset'.
  --customize <STR>     Sequence structure patterns, format: <type>,<read>:<start>-<end> separated by ';'. Types include: cb (cell barcode), umi (UMI) R1/R2 (sequence). Example:
                        "cb,R1:1-10;cb,R1:11-20;umi,R1:21-30;R1,R1:31-120;R2,R2:1-150"
  --enrichment_primers <FILE>
                        Custom inner enrichment primers file (one primer sequence per line). Required when using a custom reference database.

Analysis Settings:
  --keep_all_cells      Keep all cells in analysis without RNA data filtering. If --beadstrans is not provided, this behavior is enabled by default.
  --r2_only             Only use R2 reads for VDJ assembly. Manual setting required because Read1 assembly requirements cannot be auto-detected.
  --sample_read_pairs <INT>
                        Subsample the specified number of read pairs from the input FASTQ files (e.g., 1000000).

📝 参数说明

🔴 必需参数

⚠️ 成功分析必须指定的基本参数

参数 描述与配置
-n, --name

📋 必需

🏷️ 样本唯一标识符

功能：样本的唯一标识符（例如：sample1）
用途：用于命名输出文件和报告
显示：在生成的HTML报告中显示为样本 ID
示例： sample_VDJ_001
-r, --ref

🧬 必需

🗂️ VDJ参考数据库

功能：指定VDJ分析使用的参考数据库
内置支持：软件自带人类和小鼠的参考数据库
自定义支持：可适配主流分析软件数据库格式
支持的参考数据库：
  • human/Human：人类VDJ参考数据库（不区分大小写）
  • mouse/Mouse：小鼠VDJ参考数据库（不区分大小写）
  • 自定义路径：包含reference.json的自定义参考目录
自定义数据库要求：
  • 目录结构：必须包含reference.json配置文件
  • 序列文件：V、D、J基因段的FASTA序列文件
  • 注释文件：基因功能注释和编号信息
示例： human 或 ./custom_vdj_ref
-c, --chain

🔬 必需

🧬 受体链类型选择

核心功能：指定分析的免疫受体类型
生物学意义：不同受体类型具有不同的基因重排机制和功能
分析影响：直接影响V(D)J基因段的识别和重组分析
受体类型详细说明：
类型全称细胞来源主要功能基因重排特点
TRT-cell Receptor
T细胞受体		T淋巴细胞细胞免疫、抗原识别TCRα/β或TCRγ/δ链重组
IGImmunoglobulin
免疫球蛋白		B淋巴细胞体液免疫、抗体产生重链(H)和轻链(L)重组
示例： TR（T细胞研究）或 IG（B细胞研究）

🟢 输入文件参数

📁 选择一种输入方式：基于目录 OR 单独指定文件

参数 描述与配置
--fastqs

🔄 方式1

📂 FASTQ 文件目录

方法：基于目录的输入，自动检测
功能：流程自动检测目录中的配对读段文件
便利性：适合标准化的文件组织结构
目录结构要求：
  • 文件命名：标准的R1/R2配对文件命名格式
  • 自动检测：软件自动识别Read1和Read2文件
  • 路径格式：支持相对路径和绝对路径
示例： ./VDJ_fastq_dir
-1, --fastq1

🔄 方式2A

📄 Read1 FASTQ 文件

输入：VDJ文库的 Read1 FASTQ 文件
支持：通配符和逗号分隔的列表
内容：包含细胞条形码、UMI和部分VDJ序列信息
要求：必须与 fastq2 参数配对使用
文件格式要求：
  • 多文件支持：支持多个测序批次的文件合并
  • 通配符支持：可使用*等通配符批量指定文件
示例： sample1_L01_R1.fastq.gz,sample1_L02_R1.fastq.gz
-2, --fastq2

🔄 方式2B

📄 Read2 FASTQ 文件

输入：VDJ文库的 Read2 FASTQ 文件
支持：通配符和逗号分隔的列表
内容：主要包含VDJ重组序列的生物学信息
顺序：文件序列必须与 fastq1 完全匹配
配对关系要求：
  • 顺序一致性：R1和R2文件必须严格按相同顺序排列
  • 读段配对：每个R1文件必须有对应的R2文件
  • 质量一致性：所有文件必须来自同一测序实验
示例： sample1_L01_R2.fastq.gz,sample1_L02_R2.fastq.gz

⚠️ 输入方式选择：

  • 🔸 方式1： 使用 --fastqs 指定包含配对文件的目录
  • 🔸 方式2： 使用 -1/-2 分别指定 R1/R2 文件

📌 格式要求：

  • 多个FASTQ文件应以逗号分隔
  • R1和R2文件必须保持相同的排序顺序
  • 所有文件必须来自同一文库，测序模式和暗反应设置必须一致
  • 不同实验或样本的数据不得合并分析

🟢 基本设置参数

参数 描述与配置
-o, --outdir

📁 默认：当前目录

💾 输出目录设置

功能：指定VDJ分析结果和报告的输出目录
存储：所有分析结果将保存在此目录中
组织：自动创建结构化的子目录
示例： ./VDJ_analysis_output
-t, --threads

⚡ 默认：所有可用核心

🔧 并行处理线程数

功能：用于并行处理的CPU线程数
性能：增加线程数可显著提高分析速度
建议：根据可用CPU核心数和内存容量进行调整
示例： 16（使用16个CPU线程）
-s, --beadstrans

🔗 可选

🧬 RNA-VDJ数据整合

功能：提供RNA分析与VDJ分析之间的细胞对应关系
整合：启用基于RNA分析结果的细胞过滤功能
数据源：来自5' scRNA分析结果的singlecell.csv文件
使用要求：
  • 前置分析：需先完成同一样本的5' scRNA分析
  • 文件格式：必须是标准的singlecell.csv格式
  • 细胞匹配：基于细胞条形码进行精确匹配
整合效果：
  • 细胞过滤：仅保留RNA分析中识别的高质量细胞
  • 数据关联：建立RNA表达与VDJ重组的对应关系
  • 质量提升：提高VDJ分析结果的可靠性
示例： ./RNA_analysis/singlecell.csv
⚠️ 注意：不使用此参数时，等效于启用 --keep_all_cells 选项

🟢 文库设置参数

🔧 针对不同文库制备方法和测序策略的专业配置选项

参数 描述与配置
--darkreaction

🔧 默认：auto

🔬 暗反应循环设置

技术原理：控制VDJ文库中暗反应循环的处理方式
暗反应定义：测序过程中不进行荧光检测的循环，用于优化序列质量
自动检测：推荐使用auto模式，软件会自动分析序列长度分布
配置选项说明：
设置说明适用场景
auto自动检测（推荐）标准VDJ分析流程
R1Read1有暗反应特定暗反应设计的文库
unset无暗反应标准MGI协议
自动检测逻辑：
  • 采样分析：检查前200,000个序列的长度分布特征
  • 模式识别：根据长度分布模式和固定序列信息推断暗反应设置
  • 验证机制：检查识别结果与VDJ序列结构的一致性
⚠️ 重要提示：错误的暗反应设置可能导致条形码提取失败或VDJ序列质量下降
--customize

⚙️ 高级

🛠️ 自定义序列结构配置

高级功能：用于非标准VDJ文库设计或特殊实验需求的精确序列结构定义
优先级：覆盖darkreaction的自动检测结果
坐标系统：使用1-based坐标系统（第一个碱基为位置1）
语法格式详解：

基本格式：<type>,<read>:<start>-<end>

类型说明示例VDJ中的作用
cb细胞条形码序列cb,R1:1-10细胞身份识别
umiUMI（唯一分子标识符）umi,R1:21-30去除PCR重复和定量
R1Read1中的VDJ序列R1,R1:31-120V(D)J重组序列信息
R2Read2中的VDJ序列R2,R2:1-150完整的V(D)J序列
VDJ文库配置示例：

标准VDJ文库配置：

"cb,R1:1-10;cb,R1:11-20;umi,R1:21-30;R1,R1:31-120;R2,R2:1-150"
  • 第一个细胞条形码：R1的1-10位置
  • 第二个细胞条形码：R1的11-20位置
  • UMI序列：R1的21-30位置
  • VDJ序列部分1：R1的31-120位置
  • VDJ序列部分2：R2的1-150位置
使用注意事项：
  • 引号保护：参数必须用引号包围，避免shell解析错误
  • 坐标范围：不能超出实际读段长度
  • 生物学意义：确保VDJ序列部分能覆盖V、D、J基因段
  • 质量检查：软件会验证配置的合理性
⚠️ 风险提示：错误的自定义配置可能导致VDJ序列识别失败，建议仅在标准配置无法满足需求时使用
--enrichment_primers

🧬 自定义

🎯 富集引物配置

功能：指定用于VDJ区域特异性扩增的内部富集引物
应用：针对非人/鼠物种或自定义引物设计的VDJ文库
格式：文本文件，每行包含一个引物序列
引物文件格式要求：
  • 文件格式：纯文本文件
  • 序列格式：每行一个引物序列，仅包含ATCG碱基
  • 序列方向：与PCR扩增时使用的内引物序列一致
  • 质量要求：序列准确无误，避免影响VDJ序列识别
适用场景：
  • 自定义物种：人类和小鼠以外的模式生物VDJ分析
  • 特殊设计：使用非标准引物的VDJ文库制备
  • 研究需求：特定V、D、J基因段的靶向分析
文件示例： 
GTCCTCGGTGGCCTCCACGTG
AGCACCTGGGGCCTCGGCCAC
CCTGGACTCCTGGGCCCCAG
⚠️ 注意：使用自定义参考数据库时必须提供此参数

🚩 分析设置参数

🔧 影响VDJ分析策略和结果质量的关键设置

参数 描述与配置
--keep_all_cells

🏳️ 标志

🔓 保留所有检测细胞

功能：保留所有检测到的细胞，不使用RNA分析结果进行细胞过滤
策略：基于VDJ数据本身的质量指标进行细胞识别
自动触发：当未提供--beadstrans参数时自动启用
应用场景分析：
  • 独立VDJ分析：仅进行VDJ分析，无对应的RNA数据
  • 最大化细胞回收：保留所有可能的VDJ阳性细胞
  • 数据探索：初步评估VDJ数据质量和细胞分布
  • 比较分析：与RNA过滤结果进行对比研究
质量控制机制：
  • 基于VDJ：仅基于VDJ重组序列质量进行判断
  • UMI阈值：使用VDJ特异性UMI数量阈值
  • 重组完整性：检查V(D)J重组的完整性和准确性
⚠️ 注意：可能包含RNA表达质量较低的细胞，建议结合后续质量评估
--r2_only

🎯 标志

📖 仅使用Read2序列组装

技术背景：针对Read1仅含条形码和UMI信息的文库设计
组装策略：仅使用Read2中的生物学序列进行VDJ重组分析
手动设置：软件无法自动检测，需要根据文库设计手动指定
适用的文库设计：
  • 短Read1设计：Read1长度仅覆盖条形码和UMI区域
  • 单端VDJ序列：完整的VDJ序列全部位于Read2中
  • 成本优化设计：减少Read1测序深度以降低成本
分析影响：
  • 序列信息减少：丧失Read1中可能的VDJ序列信息
  • 重组检测：依赖Read2的完整性进行V(D)J重组识别
  • 质量要求：对Read2的序列质量要求更高
技术检查建议：
  • 序列长度分析：检查Read1是否包含生物学序列
  • 文库构建确认：与实验记录核对文库设计方案
  • 质量评估：比较使用前后的VDJ检测效果
⚠️ 重要提示：错误使用可能导致VDJ检测敏感性下降，请根据实际文库设计选择
--sample_read_pairs

🔢 可选

🎲 子采样读段对数量

功能：从输入FASTQ文件中子采样指定数量的读段对进行分析
目的：用于测试、调试或快速评估分析参数
影响：可能影响最终的细胞检测和VDJ重组定量结果
使用场景：
  • 参数测试：快速测试不同分析参数的效果
  • 计算资源限制：在资源受限环境下进行初步分析
  • 质量评估：快速评估数据质量和分析流程
  • 方法开发：算法开发和验证过程中的快速迭代
示例： 10000000（子采样10M读段对）
⚠️ 注意：子采样可能影响低频克隆型的检测，正式分析建议使用全部数据

💡 分析策略建议：

  • 首次分析： 建议使用默认参数，获得初步结果后根据HTML报告调整参数
  • 参数优化： 根据细胞回收率、VDJ检测率等指标进行针对性调整
